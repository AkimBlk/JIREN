Get Started In 5 Minutes

This page is designed for first-time users: clear steps, key rules, and quick answers. Start here whenever you are unsure what to do next.

schedule ~5 min read

1. First Steps

  1. Open your project list. Pick an existing project or create one if you are an admin.
  2. Create a sprint. Define objective, dates, and capacity.
  3. Create tickets. Use Epic, Story, Bug, or Task with clear titles and owners.
  4. Run the work. Move tickets through Kanban: To Do -> In Progress -> Done.
  5. Track outcomes. Use Analytics and project views to monitor progress.

2. Where To Go

Projects

Create and manage projects, members, and overall scope.

Backlog

Prioritize work and prepare what should enter the next sprint.

Sprint / Kanban

Execute work in progress and keep ticket states up to date.

Tickets

View and update issue details, links, tags, and attachments.

3. Rules That Prevent Most Errors

  • Only one active sprint is allowed per project.
  • A Task should be linked to a parent Story or Bug.
  • Keep ticket status flow simple: To Do -> In Progress -> Done.
  • If you cannot edit something, verify your role/permissions first.

4. Quick Questions

I cannot create a project. Why?

Project creation is restricted to users with admin privileges.

Why is Kanban empty?

Kanban shows tickets from the active sprint. Start a sprint and assign tickets to it.

How do I track delivery health quickly?

Use project details + analytics to monitor progress, capacity, and completion trends.

5. GitHub Token For Private Repositories

If your repository is private, you must provide a personal access token. Keep it secret and never share it in chat, screenshots, or commits.

  1. Open GitHub settings: Profile picture -> Settings -> Developer settings -> Personal access tokens.
  2. Choose a token type: Fine-grained token (recommended) or Classic token.
  3. Set an expiration date (short-lived is safer), then grant repository read access. For private repos, make sure the token can read repository metadata and contents.
  4. Click Generate token and copy it immediately. GitHub shows the full token only once.
  5. In JIREN, open Project -> Git Integration, enable Private Repository, paste the token, and save.
Recommended scope (minimum): read-only access to the target private repository.
